## GitHub Flow

Каждый этап начинается от актуального main в отдельной ветке. После реализации открывается PR в main.
Обязательны сборка, тесты, проверка контракта и review. Слияние выполняется после проверок.
Следующий этап начинается после слияния зависимостей. develop и релизные ветки не нужны.
Фактические даты PR, CI и merge сохраняются. Не имитировать чужое одобрение.

## Критерии готовности

Все 39 операций из docs/api/openapi.yaml реализованы с бизнес-правилами docs/api/API.md.
Проверки должны включать чужие ID во вложенных структурах и фильтрах, конкурентные изменения version,
повторы Idempotency-Key, двойной RECEIVED, рестарт заданий, устаревшие рекомендации,
ошибки CSV и числовые переполнения. HTTP-ответы проверяются против OpenAPI.
Целевые метрики производительности подтверждаются измерениями отдельно.
