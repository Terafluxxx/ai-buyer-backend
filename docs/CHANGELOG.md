# Changelog — AI Buyer Backend

Все заметные изменения backend фиксируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Версионирование — [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Создан backend на Java 21 и Spring Boot 3.5.7 с PostgreSQL и Maven.
- Добавлено расчётное ядро `RecommendationCalculator` для рекомендаций по закупкам, включая проверки граничных случаев.
- Добавлена регистрация организации и пользователя, вход и выход, получение текущего профиля и текущей организации.
- Добавлена JWT-аутентификация; пароли хешируются BCrypt, а отзыв пользовательской сессии сохраняется в базе данных.
- Добавлены товары: создание, получение списка, получение карточки, изменение и удаление.
- Добавлены операции складских остатков и учёт продаж по дням.
- Добавлена сводка продаж за выбранный период.
- Добавлены миграции базы данных Flyway и интеграционные тесты.
- Добавлены Dockerfile и Compose-конфигурация для локального запуска backend вместе с PostgreSQL.
- Добавлены GitHub Actions workflow для backend-тестов и отдельной проверки расчётного модуля рекомендаций.

### Changed
- Доступ к товарам, остаткам и продажам ограничен организацией пользователя, определённой из проверенного JWT.
- Добавлены валидация параметров и JSON, единый формат ошибок, SQL-пагинация и проверка уникальности SKU в пределах организации.
- Изменение остатков и данных продаж учитывает версию/ревизию данных; операции записи сериализуются на уровне организации.

### Security
- Добавлена изоляция данных между организациями: обращения к чужим ресурсам не должны раскрывать их существование.
- Для JWT и паролей реализованы механизмы аутентификации и безопасного хранения, описанные в README проекта.

### Known limitations
- REST-эндпоинт, который вызывает `RecommendationCalculator`, ещё не включён в текущий `main`; frontend пока содержит временную копию формулы.
- Модули поставщиков, закупок и CSV-импорта ещё не реализованы.
- Интеграционные HTTP-тесты используют H2 в PostgreSQL mode; они не заменяют полноценную проверку на реальном PostgreSQL.
