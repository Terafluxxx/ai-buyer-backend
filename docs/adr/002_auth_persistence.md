# ADR-002: Хранение авторизации

## Контекст

Контракт требует общего отзыва JWT между экземплярами и атомарной регистрации компании с пользователем.
README организации называет Spring Data JPA; исходный каркас не содержит сущностей и репозиториев.

## Решение

На этапе auth использовать Spring JDBC с явными параметризованными запросами и Spring-транзакциями.
Flyway владеет схемой. Это отклонение от заявленного JPA-стека для данного модуля;
оно не меняет HTTP-контракт и не запрещает JPA в следующих модулях.
JWT подписывается HS256 через Spring Security/Nimbus, ключ обязателен в окружении.
Отзыв sid и лимиты входа хранятся в PostgreSQL. JWT не содержит пароль или хеш.

Spring Boot 3.5.7 заменяет исходный 4.1.1; целевая Java 21 заменяет исходную Java 25.
Версии фиксированы для воспроизводимой сборки.

## Последствия

SQL и транзакционные границы видны явно. Схема тестируется миграциями.
Автоматической очистки истёкших отзывов и старых IP-bucket пока нет; это следующая эксплуатационная задача.
Общий ключ требует согласованной ротации; текущий MVP при смене ключа завершает все сессии.
